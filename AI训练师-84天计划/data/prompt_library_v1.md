## 1. 意图分类器

- **场景**：电商客服消息分类（投诉/咨询/开发票/闲聊）
- **设计理由**：五要素齐全（D15）；1-shot 简单例锚定格式（D16 数据 67%→83%）
- **效果数据**：可解析率 0%→100%（D15 before/after，n=5）；3-shot 准确率 100%（D16，n=6）
- **失败边界**：混合意图消息只判主意图；类别超过 4 个时需增加示例与枚举说明
- **参数建议**：temperature=0.2, top_p=1, max_tokens=60

```text
你是电商客服系统的意图分类器。
任务：把用户消息分类到：{intents}。
约束：只依据文本；与所有意图无关时输出"闲聊"；不要解释。
示例：发货太慢了气死了 → {{"intent": "投诉"}}
输出：只输出 JSON {{"intent": "..."}}。
用户消息：{msg}
```


## 2. 拒答守卫版分类器

- **场景**：需要'无法判断'出口的场景，防边界硬答
- **设计理由**：给模型体面退出路径 → 降编造（W2 D5 幻觉实验的缓解手段）
- **效果数据**：边界题硬答率显著下降（W2 D5 诱导实验口径）
- **失败边界**：拒答阈值难调：过松=大量无法判断，过紧=形同虚设
- **参数建议**：temperature=0.2, max_tokens=80

```text
你是意图分类器。类别：{intents}。
若消息信息不足或跨类别无法判定主意图，输出 {{"intent": "无法判断", "reason": "..."}}。
只输出 JSON。消息：{msg}
```


## 3. 结构化抽取

- **场景**：从客服对话抽取订单号/问题类型/诉求字段
- **设计理由**：显式允许 null → 防'硬凑字段值'（幻觉的另一种形态）
- **效果数据**：null 出口使编造字段显著减少（W2 D5 任务超纲类缓解）
- **失败边界**：对话含多个订单号时只取一个；需在业务侧定义取哪个
- **参数建议**：temperature=0.2, max_tokens=120

```text
你是信息抽取器。从下面对话抽取字段，输出 JSON：{{"order_id": "字符串或null", "issue": "...", "demand": "..."}}
约束：字段不存在时用 null，禁止编造。对话：{dialog}
```


## 4. 保事实摘要

- **场景**：长客服工单摘要，给人工复核用
- **设计理由**：'不添加'约束压制摘要幻觉；字数约束控制输出成本
- **效果数据**：人工抽检事实错误率低（W2 D5 判定纪律沿用：先定抽检标准）
- **失败边界**：对话极长（>窗口一半）时需先分段摘要再汇总（map-reduce）
- **参数建议**：temperature=0.3, max_tokens=200

```text
你是摘要助手。输出一段 ≤{n} 字的对话摘要，要求：保留订单号/金额/时间等事实，不添加对话中没有的信息。
对话：{dialog}
```


## 5. 情感与强度打分

- **场景**：用户情绪监测（1-5 分），预警升级人工
- **设计理由**：few-shot 锚定分数粒度；结构化输出供规则引擎消费
- **效果数据**：打分任务低温保证可复现（D17 评测参数纪律）
- **失败边界**：反讽/阴阳怪气易判低分——需人工抽检 5% 校准
- **参数建议**：temperature=0.2, max_tokens=40

```text
你是情绪评分器。给消息的情绪强度打 1-5 分（5=极度愤怒）。
约束：只依据文本语气评分，不考虑标点多少。
示例：'等了三天了？？？？' → 4
只输出 JSON {{"score": 数字, "trigger": "是否需人工, true/false"}}。
消息：{msg}
```


## 6. 数据清洗助手

- **场景**：标注语料的规范化（错别字/全半角/冗余空白）
- **设计理由**：uncertain 列表=主动上报不确定项，符合质检口径（宁可标注存疑不可静默改错）
- **效果数据**：清洗可解释、可抽查（W4 清洗流水线的前置组件）
- **失败边界**：行业术语可能被'纠正'成常用词——需提供术语白名单
- **参数建议**：temperature=0.1, max_tokens=300

```text
你是文本清洗助手。清洗下面的文本：修正错别字、统一全半角、去除冗余空白和表情。
约束：不改变语义；不确定的修正保持原样并列出。
输出 JSON {{"clean": "...", "uncertain": ["..."]}}。文本：{text}
```


## 7. 标注规范问答

- **场景**：让模型按规范文档回答标注员的问题（W4 配套）
- **设计理由**：限定知识来源+未覆盖出口 → 防规范问答幻觉（RAG 思想的最小实现，W7 展开）
- **效果数据**：越界问题拒答率可测（诱导规范外问题即 W2 D5 方法复用）
- **失败边界**：规范文档太长需分段检索（引出 W7 RAG）
- **参数建议**：temperature=0.2, max_tokens=200

```text
你是标注规范助手。仅依据下面的规范回答，规范未覆盖时回答'规范未覆盖，请提交仲裁'。
规范：{rules}
问题：{question}
```


## 8. 评测裁判

- **场景**：给模型回答按细则打分（W6 LLM-as-Judge 预演）
- **设计理由**：issues 字段强制给理由 → 分数可归因（W6 归因分析的基础）
- **效果数据**：裁判波动性必须实测：同输入跑 3 次看一致性（D6 多样性方法复用）
- **失败边界**：裁判偏好长回答（长度偏差）——细则里显式声明'长度不影响分数'
- **参数建议**：temperature=0~0.2（必须低温）, max_tokens=100

```text
你是评测裁判。按细则给回答打 1-5 分。
细则：{rubric}
问题：{q}
回答：{answer}
约束：严格按细则评分，回答长度不影响分数。
只输出 JSON {{"score": 1-5整数, "issues": ["..."]}}。
```


## 9. 多轮指代消解

- **场景**：追问里'它/那个'指什么（W6 多轮评测预演）
- **设计理由**：强制先解指代 → 输出可检查（把'理解过程'显性化）
- **效果数据**：历史完整性是多轮评测红线（D5 关键信息实验：滑窗丢订单号实证）
- **失败边界**：历史被截断时指代必错——调用方须保证保头保尾策略
- **参数建议**：temperature=0.2, max_tokens=150

```text
你是多轮对话助手。回答最后的问题；若'它/那个'等指代不明确，先指出指代对象再回答。
对话：{history}
最后问题：{question}
```


## 10. SFT 样本生成器

- **场景**：造 SFT 数据的对话样本（W4 造数据的辅助）
- **设计理由**：变量化批量生成 → 数据增强；JSON 结构 = 直接可入库格式（D3 闭环消费）
- **效果数据**：生成样本必须 100% 人工审核后才可入训练集（质检纪律）
- **失败边界**：生成样本同质化（句式趋同）——需多样化 topic/tone 组合并去重
- **参数建议**：temperature=0.8（生成任务可高温）, max_tokens=400

```text
模拟一条电商客服对话（2-3 轮），主题：{topic}，用户语气：{tone}。
输出 JSON {{"turns": [{{"role": "user", "content": "..."}}, ...]}}。
约束：对话必须自然，不要出现'作为AI'等出戏表述。
```
