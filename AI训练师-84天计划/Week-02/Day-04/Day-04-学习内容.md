## 2. 训练四阶段：每阶段数据长什么样（W1 D5 的升级版）

| 阶段 | 数据形态（能画出来的那种） | 规模量级 | 谁负责 |
| --- | --- | --- | --- |
| ① 预训练 | 纯文本流：`"今天天气很好。明天……"`（无标注，滑窗预测下一 token） | 万亿 token | 算法团队 |
| ② SFT | 指令对：`{"instruction": "把这段话总结成一句话", "output": "……"}` | 1万~100万条 | **训练师/数据团队主导** |
| ③ 偏好对齐 | 对比对：`{"prompt": "…", "chosen": "好回答", "rejected": "差回答"}` | 10万~千万条 | **训练师主导** |
| ④ 持续迭代 | Bad Case 修复数据（本质是 ②③ 的定向补强） | 持续小批量 | **训练师日常** |

**两个高频面试题的答案骨架**：
- "SFT 数据多少条够？"——质量 > 数量。LIMA 论文证明 1000 条高质量数据就能对齐出不错的效果；但覆盖度（任务类型/难度/失败模式）必须够
- "SFT 和 RLHF 什么关系？"——SFT 教"该做什么"（示范），RLHF/DPO 教"什么更好"（比较）；SFT 是地基，对齐是精修

## 3. SFT 三种数据格式（今天全转一遍）

| 格式 | 结构 | 谁在用 |
| --- | --- | --- |
| **Alpaca** | `instruction / input / output` 三字段 | 学术界、开源数据集最常见 |
| **ShareGPT** | `conversations: [{from, value}, ...]` 多轮 | 真实多轮对话数据 |
| **OpenAI messages** | `messages: [{role, content}, ...]` | API 事实标准，各家兼容 |

**同一份样本三种格式的互转是训练师的基本功**——下游训练框架（LLaMA-Factory 等）各吃各的格式，你交的数据必须能转。

## 6. 与测试工作的类比（面试口语）

- 三种格式互转 ≈ 接口协议适配——同一业务数据在不同系统间的 schema 映射，**你做过多少次字段映射了？**
- 第⑤段 schema 校验 ≈ 数据入库前的接口契约测试——**格式错一条，训练框架整批报错**
- 质量锚点（LIMA 1000 条）≈ 测试用例不求多求覆盖——**面试敢说"1000 条精选数据"这个数字，直接超过 80% 候选人**
