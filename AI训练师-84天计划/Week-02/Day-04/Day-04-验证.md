# 验证 · Day 11 · 训练四阶段 + SFT 格式

## 一、自测题（口答）

1. 为什么多轮对话数据不能用 Alpaca 格式表示？（看字段设计）
2. 一条偏好数据最少要几个字段？"chosen"和"rejected"必须满足什么条件才有训练价值？
3. 预训练数据要清洗，SFT 数据也要清洗——两者清洗的侧重点有什么不同？
4. "模型幻觉了"应该造什么数据来修？走 SFT 还是走偏好？各自怎么造？
5. JSONL 和 JSON 的区别？为什么训练数据都用 JSONL？

<details><summary>参考答案</summary>

1. Alpaca 是"instruction/input/output"单轮三元组，没有消息顺序和角色序列字段；多轮对话需要有序的 role 序列，Alpaca 表达不了上下文依赖。
2. 3 个：prompt、chosen、rejected。有价值的前提：两条回答在"要优化的维度"上差异真实且可解释（如一个有引用一个编造）——差异随机或都差，模型学不到方向。
3. 预训练清洗侧重：去重（网页重复极多）、去噪（乱码/广告/导航页）、质量过滤（语言检测、启发式打分）；SFT 清洗侧重：格式合规（schema 校验）、回答质量（事实性/有用性）、指令-回答匹配度、安全红线。
4. 先归因：若是"不知道却说"（编造），优先偏好数据（chosen=承认不知道+给出正确路径，rejected=编造答案）；若是"答非所问/格式错"，用 SFT 修正示范。原则：缺知识 → RAG/补充语料；行为错 → 对齐数据。
5. JSON 是整个文件一个 JSON 值；JSONL 每行一个独立 JSON 对象。训练数据用 JSONL：流式逐行读取（内存友好）、可断点续读、单行损坏不废整批、方便逐条校验和追加。
</details>
