# 验证 · Day 10 · 三种架构 + BPE

## 一、自测题（口答）

1. BERT 为什么不能直接当对话模型用？（2 个原因）
2. BPE 训练时合并的是"字符对"还是"token 对"？为什么这个区别重要？
3. 为什么换一个模型（GPT→Qwen）后，同一份评测集的 token 统计要重算？
4. 词表越大越好吗？词表 100 万会有什么问题？
5. 评测一个"长文档问答"任务时，为什么中文文档比等长的英文文档更容易触发上下文截断？

<details><summary>参考答案</summary>

1. ①BERT 是双向注意力 + MLM 训练目标（完形填空），不会"从左到右生成"，没有自回归解码能力；②预训练目标与对话任务不匹配，需大改架构。它擅长的是理解类任务（分类/检索）。
2. 合并的是"token 对"（初始时 token=字符，之后逐步变成更长的块）。重要在于：每轮合并基于上一轮结果，高频序列会滚雪球成长 token——"the"很快成为单 token，而低频词永远停在碎片级。
3. 不同模型用不同分词器/词表（BPE 变体、训练语料不同），同一文本切出的 token 序列和数量都不同——涉及计费、上下文占用的结论全部失效。
4. 不是。词表大：embedding 层和输出层参数平方级膨胀、低频 token 学不充分（训练欠拟合）、生僻 token 会被滥用过拟合；太小则序列过长。主流在 3 万~25 万。
5. 中文 1 字≈1.5-2 token，同样 1 万字的文档中文占的 token 多约 50-100%，更容易顶到上下文窗口上限——评测时要用 tiktoken 先算而不是看字数。
</details>
