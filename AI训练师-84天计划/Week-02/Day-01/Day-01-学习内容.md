## 2. 精读方法（不是通读，是按问题找答案）

读 https://jalammar.github.io/illustrated-transformer/（有中文翻译版，搜"Illustrated Transformer 中文"），**带着 4 个问题读**：

1. 一个词进模型前先变成什么？（→ 词嵌入 Embedding + 位置编码 Positional Encoding）
2. "Attention"到底在算什么？（→ 每个词对其他词的"关注度"加权）
3. 为什么要多头（Multi-Head）？（→ 多组注意力各自关注不同关系：语法/指代/语义）
4. 输出层怎么变成"下一个词"？（→ 线性层 + softmax 概率）

读完合上页面，**口述一遍完整流程**（录音 3 分钟）。讲不顺的地方就是明天 D2 要手推的部分。

## 3. 核心概念速记（今日只记 3 个）

| 概念 | 一句话定义 | 面试怎么说 |
| --- | --- | --- |
| Embedding | 把 token 映射成一个高维向量（如 4096 维），语义相近的词向量距离近 | "词变成空间里的点，意思近的点靠得近" |
| 点积相似度 | 两个向量逐元素相乘再求和，值越大越"相关"——**这就是 Attention 的原材料** | "用点积衡量相关性，不用定义规则" |
| 位置编码 | 给每个 token 加一个"位置签名"，因为 Attention 本身不知道词序 | "模型天生是'词袋'，位置信息要外加" |

## 4. 今日代码（`day01_embedding_similarity.py`）

用玩具词向量（4 维）亲手算相似度矩阵，验证三件事：
1. 语义相关的词（"猫"/"狗"）点积高——**即使向量是人造的**
2. Attention 第一步就是"每个词 × 所有词"的点积——**你已经手算过 Attention 的核了**
3. 归一化（softmax 预演）把相似度变成"关注度权重"（加和为 1）

## 6. 与测试工作的类比（面试口语）

- Embedding 空间 ≈ 用例的"特征空间"——相近输入聚在一起，**聚类后的簇边界就是该设计边界用例的地方**（W8 Bad Case 归因会用这个思路）
- Attention 点积 ≈ 关联性度量——你在缺陷分析里找"相似历史缺陷"的逻辑，模型自己学会了
- 位置编码缺失 ≈ 测试步骤乱序执行——结果对但过程错，很多 Bug 就藏在顺序里
