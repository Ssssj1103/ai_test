# 验证 · Day 13 · 采样参数网格

## 一、自测题（口答）

1. temperature=0 时模型还有随机性吗？为什么同参数多次调用输出仍可能不同？
2. top_p=0.5 会发生什么？什么任务适合这么激进？
3. "temperature 调高 + top_p 调低"组合是什么效果？（提示：一个放大一个截断）
4. 评测裁判任务（让 LLM 给另一个模型的输出打分）为什么必须低温？
5. 如果业务方要求"每次回答一模一样"，你能做到吗？差多少？

<details><summary>参考答案</summary>

1. T=0 是贪心解码（取 argmax），无采样随机性；但服务端负载均衡、批处理顺序、浮点并行非结合性、模型热更新都会引入残余波动——所以"确定性"是工程近似，评测靠"多次运行一致性统计"兜底。
2. 只在累计概率前 50% 的词里采样，长尾被砍掉一半以上。适合抽取/分类/格式化任务；创作任务会明显呆板。
3. 高温把分布摊平（低概率词概率上升），低 top_p 又把摊平后的候选砍掉——效果混乱：多样性来源被截断，但保留的头部候选内部仍在高随机跳变。工程上视为"失控组合"，禁用。
4. 裁判输出要稳定：同一份被测输出，两次打分不同 = 评测集失效。低温让裁判可复现，否则你测的是裁判的心情而不是模型。
5. 不能 100%，能到"绝大多数一致"（T=0 + 固定模型版本 + 记录日期）。诚实回答 + 给出兜底方案（输出缓存/哈希比对）比拍胸脯加分。
</details>
