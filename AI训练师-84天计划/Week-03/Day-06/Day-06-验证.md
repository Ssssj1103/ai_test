# 验证 · Day 20 · Prompt 模板库 v1

## 一、自测题（口答）

1. "模板"和"库"的区别是什么？一句话说清。
2. 失败边界应该怎么发现？凭空想出来的失败边界可信吗？
3. 模板里的 {变量} 渲染时缺变量会怎样？这个设计为什么是"fail fast"？
4. 模板 8（评测裁判）的 temperature 该设多少？为什么这个模板对参数最敏感？
5. 库的"版本管理"怎么做？模板 v1 改了一个示例，怎么追踪影响？

<details><summary>参考答案</summary>

1. 模板 = 一段提示词文本；库 = 模板 + 场景 + 设计理由 + 效果数据 + 失败边界 + 参数建议。库是可审计、可复现的资产，模板只是文本。
2. 应该从实验来：把模板故意喂边界输入（超长文本/混合意图/乱码），记录失败模式。凭空想的边界没有数据支撑，等于没写——和"没跑过的测试用例不是用例"同理。
3. 直接抛 KeyError/自定义错误并指出缺哪个变量。因为缺变量渲染出的残缺提示词可能"看起来能跑"但效果异常，错误被延迟到结果层面才发现，排查成本高数倍——尽早暴露、信息完整。
4. 0~0.2。裁判输出直接当评测分数，波动=评测噪声；同一被测对象两次打分不同，整个评测失效——所有"打分类"模板都是低温。
5. 库文件进 Git：每次修改一个 commit，效果数据标注"基于哪个版本测的"。改模板后要用原测试集重跑（回归测试），效果数据更新并记录变更原因——模板库的回归测试思维。
</details>
