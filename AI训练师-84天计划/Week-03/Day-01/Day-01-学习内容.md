## 2. Prompt 五要素（面试必答框架）

| 要素 | 作用 | 反例 → 正例 |
| --- | --- | --- |
| 角色 Role | 锚定语气和知识域 | 无 → "你是电商客服质检员" |
| 任务 Task | 动词开头，一件事 | "帮我看看这个" → "判断以下消息的意图类别" |
| 约束 Constraint | 边界：做什么/不做什么 | 无 → "不确定时回答'无法判断'，不要猜" |
| 输出格式 Format | 可解析的结构 | 自由文本 → "只输出 JSON：{intent: ...}" |
| 示例 Example | 少量样例锚定行为 | 无 → 1-3 个 few-shot（明天 D2 深入） |

**记忆法**：R-T-C-F-E（人-事-界-形-例）。写任何业务提示词先过这五项检查。

## 3. 为什么"结构化提示词"有效（机制解释）

- **降低熵**：约束和格式把模型的"可能输出空间"砍小，命中期望的概率自然上升
- **对齐评测口径**：格式固定后，你的评测脚本才能批量解析——**格式化输出是自动评测的前提**
- **防幻觉**："不确定时明确说"这类约束显著降低编造率（W2 D5 幻觉实验的缓解手段之一）

## 6. 与测试工作的类比（面试口语）

- 五要素 ≈ 测试用例的"前置条件+步骤+预期结果"——**没写预期结果的用例等于没写**，没写输出格式的提示词同理
- 格式合规率统计 ≈ 接口响应 schema 校验——你测 API 时已经在做的事
- before/after 量化 ≈ 性能优化前后压测对比——**没有数字的改进在评审会上站不住**
