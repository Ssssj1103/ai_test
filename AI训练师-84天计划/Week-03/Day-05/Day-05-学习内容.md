## 2. 多轮对话的三个管理问题

| 问题 | 说明 | 方案 |
| --- | --- | --- |
| 历史从哪来 | 模型无记忆，"多轮"=每轮把历史全部重发 | 对话管理器维护 messages 列表 |
| 超出窗口怎么办 | 历史越滚越长，顶到上下文上限 | Token 预算 + 截断策略 |
| 截断丢上下文怎么办 | 第一轮"我叫小张，手机 1234"被截掉，后面全乱 | 策略性保留 |

**三种截断策略**（今天全实现）：
1. **滑窗**（sliding window）：保留最近 N 轮——简单粗暴，早上下文必丢
2. **保头保尾**：永远保留 system + 第一轮，再拼最近的轮次——兼顾"设定"和"近期"
3. **摘要压缩**：把老历史让模型压缩成一段摘要塞回去——最贵但最完整（今天讲原理，不实装）

## 3. Token 预算的计算（ tiktoken 实测）

```
总预算 = 模型窗口（如 128K）
可用历史预算 = 总预算 − 系统提示词 − 本轮用户输入 − max_tokens（预留输出）
```

**纪律**：预留输出空间！历史塞满窗口 → 输出被截 → 看起来像"模型坏了"。这是新手最常踩的坑。

## 4. 今日代码（`day05_multiturn.py`）
