# 验证 · Day 06 · LLM API 调用与采样参数

## 一、自测题（口答）

1. `temperature=0` 时模型输出是 100% 确定的吗？为什么评测时还要跑多次抽样对比？
2. 请求返回 429 状态码是什么意思？脚本该怎么处理？400 呢？
3. 为什么把 Key 放环境变量而不是直接写在代码里？（2 个理由，其一与 Git 有关）
4. system 消息和 user 消息谁优先级高？评测脚本里 system 一般放什么？
5. 一次调用返回的 usage 里有哪些字段？怎么算这次调用的成本？

<details><summary>参考答案</summary>

1. 不是 100%。温度 0 只是取概率最高的 token，但服务端负载均衡、浮点并行计算的非确定性、模型版本更新都会引入波动——所以"可复现"是工程目标而非数学保证，评测要靠"多次运行统计一致性"来兜底。
2. 429 = 请求过于频繁（限流），应等待后重试（脚本用指数退避 2s/4s/8s）；400 = 请求参数错误，重试没用，要修代码（打印响应体定位字段错误）。
3. ①代码会进 Git 仓库，Key 写死一旦推送就永久留在历史里，必须换 Key；②环境变量便于多环境（本地/CI）切换同一份代码。
4. system 优先级更高（模型被指示以 system 为准则）。评测脚本里 system 放评分细则/角色设定/输出格式约束，user 放被测的输入样本。
5. usage 含 prompt_tokens（输入）、completion_tokens（输出）、total_tokens；成本 = 输入 token × 输入单价 + 输出 token × 输出单价（glm-4-flash 单价 0，但要养成记录习惯，换收费模型直接复用）。
</details>
