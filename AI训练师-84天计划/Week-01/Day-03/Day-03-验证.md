# 验证 · Day 03 · 评测指标

## 一、自测题（口答）

1. 1000 条消息里只有 20 条投诉。模型"全部判非投诉"的准确率是多少？这个指标还能用吗？为什么？
2. 投诉检测场景，把判定阈值从 0.5 降到 0.3，精确率和召回率各怎么变？
3. F1 为什么用调和平均而不是算术平均？（提示：想想 P=0.01, R=1.0 时两种平均的差别）
4. AUC=0.5 说明什么？AUC=0.95 呢？
5. 评测集和测试集的关系：LLM 评测里"测试集"对应什么？

<details><summary>参考答案</summary>

1. 98%。不能用——类别极不平衡时准确率会被多数类"撑高"，98% 还不如专门写一条规则。应看少数类的召回率/精确率，或用 F1、AUC。
2. 精确率降、召回率升——阈值降低意味着更多消息被判为投诉，抓得更多（召回↑）但误报也多（精确↓）。
3. 算术平均=(0.01+1.0)/2≈0.5，看起来还行；调和平均=2×0.01×1/1.01≈0.02，暴露短板。F1 的设计意图是"一项接近 0 就整体接近 0"。
4. 0.5=随机瞎猜（模型没有任何排序能力）；0.95=随机取一正一负样本，模型给正样本打分的概率 95%。
5. LLM 评测里"测试集"= 人工构建的评测集（含标准答案或评分细则），它绝不能参与 Prompt 调优决策，否则就是验证集泄漏。
</details>
