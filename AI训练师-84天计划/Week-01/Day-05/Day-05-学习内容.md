## 2. Tokenizer：文本进模型前的第一步

### 2.1 为什么不按"字/词"直接编码？

- 按字：序列太长，"上下文窗口"装不下多少内容
- 按词：词表爆炸（新词、错拼、中英混排永远数不完）
- **BPE（字节对编码）折中方案**：从字符开始，反复合并"最高频的相邻对"，最终得到 3 万~20 万个 token 的词表——高频词短、低频词拆碎

### 2.2 Token 的三个实用事实（面试高频）

1. **中英文 token 数不同**：英文 1 token≈0.75 个单词；中文常见 1 字≈1-2 token——**同样内容中文更贵、上下文"装得更少"**（影响 API 计费和窗口占用）
2. **模型看不见字符**：它只认识 token ID。GPT 系把 "hello" 看成 1-2 个 ID，把生僻字拆成 UTF-8 字节
3. **上下文窗口按 token 计**：128K 窗口 ≈ 英文 10 万词 ≈ 中文 6-8 万字（粗略，模型而异）——评测集太长会"爆窗"

## 3. 训练四阶段（背下"每阶段喂什么数据"）

| 阶段 | 喂什么数据 | 学到什么 | 训练师 involvement |
| --- | --- | --- | --- |
| ① 预训练（Pre-training） | 万亿级网页/书籍/代码（无标注，预测下一个 token） | 语言、知识、推理的"底子" | 几乎不参与（算力游戏） |
| ② SFT 监督微调 | 几万~百万条「指令→高质量回答」对 | 听懂指令、按格式回答 | **你的主战场：造 SFT 数据**（W4） |
| ③ 偏好对齐（RLHF/DPO） | 「同一个问题，好回答 vs 差回答」对比对 | 有用、诚实、无害的"价值观" | **你的主战场：偏好数据**（W4） |
| ④ 持续学习/迭代 | Bad Case 修复数据、新知识 | 持续改进 | **你的日常：归因 → 造数据 → 再训** |

> 一句话总结：**预训练是"读书"，SFT 是"学做人"，对齐是"学做好人"，持续迭代是"复盘改进"——训练师从第二阶段起全面接管。**

## 4. 幻觉：为什么必然发生（面试必问）

**定义**：模型生成流畅自信但事实错误的内容。

**四个成因**（每个配一个缓解手段）：

| 成因 | 直觉解释 | 缓解手段 |
| --- | --- | --- |
| 知识缺失 | 训练数据里根本没有（或太旧） | RAG 外挂知识库、联网搜索 |
| 记忆混淆 | 万亿数据里相似内容打架 | 引用溯源、要求给出处 |
| 过度自信 | 训练目标是"像训练数据"，承认不知道会被降分 | 拒答机制、允许说"我不知道" |
| 指令误解 | 理解偏差一路放大 | Prompt 明确化、Few-shot 示例 |

**训练师视角**：幻觉不是 bug，是"下一词预测"这个训练目标的固有属性——**你的工作就是用评测把幻觉量化（幻觉率），再针对性造数据/改 Prompt 降下来**。这正是 W6-W8 的内容。

## 6. 与测试工作的类比（面试口语）

- Tokenizer 词表 ≈ 系统支持的"输入协议"——超协议的输入（生僻字）会被拆解甚至丢信息，**构造边界用例时就要拿生僻字/emoji/中英混排去打**
- 上下文窗口 ≈ 内存限制——超出就截断，"最早的内容先丢"，评测长文档任务时必测
- 幻觉四个成因 ≈ 缺陷根因分类——你归因时用的就是测试的 fault localization 思路
