## 2. 一条标注 → 一条 SFT 样本：缺的是"任务设定"

标注结果只有 `(消息, 标签)`，模型需要知道**要它干什么**。所以 SFT 样本三件套：

```
instruction  任务说明书（分类到哪几个类、按什么规则、输出什么格式）
input        用户消息（原始输入，一个字不改）
output       标准答案（你标注的标签）
```

**指令变体的意义**：同一个任务写 2-3 版 instruction（简洁版/详细版/带判例版），随机分配给样本。这样训练出的模型对"指令怎么写"更鲁棒——只见过一种措辞的模型，换种问法就废（过拟合指令措辞 ≈ 测试用例只覆盖一条路径）。

## 3. 质量过滤漏斗（今天的主线动作）

```
100 条标注结果
 ├─ ① 剔除跳过条（label 为空）——昨天的 pending 不许混进来
 ├─ ② 剔除无效条（"无效：不入集"）——它们不是合法类别
 ├─ ③ 去重（完全重复 + 去空格标点后仍重复的"近重复"）
 ├─ ④ 长度护栏（input 过短 <2 字 或 过长 >200 字 → 可疑，人工过目）
 └─ ⑤ 分布体检（每类条数、"其他"占比 ≤15% 红线复查）
→ 最终训练样本（带 difficulty 标签：边界例单独标记，供 D6 分层抽样）
```

**漏斗每一步都要留下"剔了几条、为什么"的账**——这是 D6 质检报告和简历上"数据质量意识"的证据。

## 6. 与测试工作的类比（面试口语）

- instruction 变体 ≈ 同一功能的等价测试路径——**覆盖多种"问法"才能测出真鲁棒性**
- 过滤漏斗 ≈ 缺陷过滤流程（重现→确认→关闭）——每一步有账，最后数字才可信
- source_id 回溯 ≈ 缺陷单关联用例 ID——**数据出问题时能追到原始标注，这是数据治理的底线**
