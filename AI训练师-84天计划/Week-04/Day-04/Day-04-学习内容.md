## 2. 一致性指标：从"看着差不多"到"可计算"

| 指标 | 公式 | 怎么读 |
| --- | --- | --- |
| 自一致率 | 重标一致条数 / 重标总条数 | 检验规范在你自己手里是否稳定（隔了时间还稳定 = 真理解了规则） |
| 两人一致率 | 一致条数 / 总条数 | W5 陌生人试标时用；<95% 先查规范再查人 |
| Kappa | （P_o − P_e）/（1 − P_e） | 剔除"瞎蒙也能对上的部分"；W5 详讲，今天只混个脸熟 |

**经验阈值**：自一致率 ≥95% 合格；90-95% = 边界规则不够具体；<90% = 规范有结构性问题（不是你不认真）。

**测试类比**：重标 ≈ 回归测试用例跑两遍。两遍结果不一致 ≈ 用例存在**不稳定步骤（flaky）**——你不怀疑"测试执行者"，你怀疑用例本身。

## 3. 重标样本怎么选（不是随便抽）

```
① 全部跳过条目（上次拿不准的）
② 耗时 TOP10（上次卡壳的）
③ 每类随机 2 条普通例（防"只测难题"的偏差）
④ 昨天问题日志涉及的条目
```

**为什么 ①② 优先**：一致性要在"最容易不一致"的地方验证。全抽简单例 = 100% 一致但毫无信息量——和你做冒烟测试只挑主干路径是同一个错误。

## 4. 分歧仲裁的输出物（今天的核心交付）

每个分歧样本必须产出一行仲裁记录：

```
消息：「＿＿」｜第一次: 催发货 ｜第二次: 投诉 ｜仲裁: 催发货
依据：规范④「有投诉词但诉求核心是催进度」
动作：无需改规范 / 补充规范④判例 / 修正规范③优先级
```

**仲裁纪律**：不允许"都对"或"都对吧"——两次必须裁决出唯一结果，否则这条进 D5 的剔除名单。分歧无法仲裁 = 规范缺陷，不是数据缺陷。

## 7. 与测试工作的类比（面试口语）

- 重标 ≈ flaky 用例检测——**结果不稳定的用例/标注，先查设计再查执行**
- 分类别一致率 ≈ 按模块统计缺陷密度——改进资源投向热点区
- 仲裁记录 ≈ 缺陷评审结论（有效/无效/延期）——**每个争议都要有结论和依据，不留悬案**
