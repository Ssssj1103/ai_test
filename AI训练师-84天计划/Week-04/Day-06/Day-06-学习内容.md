## 2. 划分的四条纪律（每条违反 = 评测结论作废）

| 纪律 | 为什么 | 测试类比 |
| --- | --- | --- |
| **分层抽样**（按类别比例切） | 小类别若没进 val/test，那类效果根本测不到 | 兼容性测试必须覆盖小众平台 |
| **source 不可泄漏**（同源消息不同变体不跨集合） | 近亲样本跨集合 = 模型"背过题"，val 指标虚高 | 用例和数据准备自证清白 |
| **可复现**（固定种子 + 记录划分脚本版本） | 换个种子指标就变 → 结果不可信 | 回归必须跑同一套用例 |
| **边界例配额**（boundary 样本在 val/test 里的占比 ≈ 训练集，允许 ±10% 波动） | 评测要在难的地方测，不能只测简单题 | 验收测试难度 ≥ 冒烟测试 |

## 3. 数据集质检报告的结构（M1 验收文件骨架）

```
① 数据集概览    规模 / 类别分布 / instruction 变体分布 / schema 版本
② 质量过程      过滤漏斗账本（引用 D5 报告）+ 一致率结论（引用 D4 报告）
③ 划分方案      比例 / 分层方式 / 种子 / 边界例配额 / 泄漏检查结果
④ 已知局限      规模小（<200）、"其他"占比、单一标注员、模拟数据——如实写
⑤ 使用建议      怎么加载 / 怎么引用版本 / 复现命令
```

**④ 是诚信条款**：数据集的"已知局限"写得越具体，作品集越可信。面试官对"完美数据集"的第一反应是怀疑。

## 6. 与测试工作的类比（面试口语）

- 分层抽样 ≈ 测试矩阵按平台×优先级覆盖——**覆盖率是设计出来的，不是跑出来的**
- 泄漏检查 ≈ 测试数据和预期结果不能互相抄——**自证循环是评测的大忌**
- 可复现种子 ≈ 测试环境快照——**没有环境记录的测试结果无法归因**
