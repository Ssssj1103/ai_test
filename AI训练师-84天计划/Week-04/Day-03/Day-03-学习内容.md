## 2. 为什么必须亲手标一遍（面试必答）

| 不亲手标的后果 | 面试怎么讲 |
| --- | --- |
| 规范里的规则是"想象出来的"，和真实数据的分布对不上 | 「我先自己标 100 条，规范问题日志里有 7 条是标注时发现规范没覆盖的——不实操发现不了」 |
| 不知道一条数据要标多久 → 排期拍脑袋 | 「我实测平均 22 秒/条，边界例 60 秒+，据此推算项目排期」 |
| 无法评估规范可执行性 → 一致性崩了才发现 | 「标注顺畅度是规范质量的先行指标：卡壳点 = 边界盲区」 |

**测试类比**：亲手标注 ≈ 执行自己写的用例。写用例的人不执行，永远不知道第 3 步没法操作。

## 3. 标注工具的核心设计（你会用到的功能）

```
1. 断点续标：中途退出不丢进度（读已完成的 CSV，跳过已标条目）
2. 每条计时：耗时数据是排期依据，也是"卡壳探测器"（>45s 自动提示记一条问题）
3. 规范问题日志：标注中随时按 p 键记"规范没说清的地方"→ 这是 D4 修订规范的原料
4. 跳过 + 无效两类出口：拿不准标 0（跳过）；与业务无关的场景外消息按 i 标"无效：不入集"
   （后者是 D2 规范④的要求——"其他"是合法类别要入集，"无效"是质量不合格不入集，两者不能混）
```

**纪律红线**：拿不准 → 跳过并记日志，**不许硬标**。硬标的脏数据在 D5 清洗时要去掉，而日志能换来规范升级——同一个动作，一个亏一个赚。

## 4. 今日代码（`day03_label_tool.py`）

- 内置 100 条消息池：70 条普通例 + 18 条边界例（D2 四类，含近重复变体）+ 6 条无语义噪声 + 6 条"手滑重发"（后者是给 D5 去重练习留的靶子）
- 交互模式（默认）：逐条显示 → 选类别（1-6）/ `i` 无效不入集 / `0` 跳过 / `p` 记规范问题 / `s` 保存退出
- `--auto` 模式：内置一个"带噪声的规则标注员"自动标完（用于无终端环境回归验证，**不是**让你跳过实操的借口）
- 产出：`data/day03_labeled.csv`（id/消息/标签/耗时/备注）+ `data/day03_session_log.md`（统计 + 问题日志）

## 6. 与测试工作的类比（面试口语）

- 标注计时分布 ≈ 用例执行时长统计——**长尾条目就是设计盲区**
- 规范问题日志 ≈ 用例评审意见清单——评审意见多少条、什么类型，直接反映文档质量
- 跳过纪律 ≈ 测试里"block 的用例不许标记 pass"——**宁可阻塞不可造假**
